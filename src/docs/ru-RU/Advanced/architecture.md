# Архитектура

## Компоненты

- **Настольное приложение**: Tauri v2 с системным WebView.
- **Бэкенд**: Rust на Tokio, рабочее пространство внутренних крейтов.
- **Интерфейс**: Svelte 5 + SvelteKit + TypeScript, компилируется как статический сайт.

Фронтенд отправляет команды бэкенду через Tauri IPC. Бэкенд отвечает событиями `app-event` и потоками журналов; интерфейс обрабатывает их для обновления загрузок, инстансов, состояния запуска и консоли.

## Крейты рабочего пространства

| Крейт | Назначение |
| --- | --- |
| `aqua` | Загрузка версий Minecraft, загрузчиков и JRE; манифесты, assets, библиотеки и источники загрузок. |
| `zellkern` | Модели манифестов, разрешение версий, утилиты Forge, сборка аргументов и `LaunchConfig`. |
| `launchwerk` | Подготовка и запуск процесса Java, распаковка нативных библиотек и управление жизненным циклом. |
| `cubrinth` | Установка модпаков `.mrpack` и связанные утилиты. |
| `communicator` | Клиент Discord RPC. |
| `ablage` | Локальное хранилище с версионируемым кешем для сериализованных данных. |
| `src-tauri` | Приложение Tauri: команды, сервисы инстансов, настройки, аутентификация, очередь загрузок и события. |

## Структура репозитория

```
src/                  # Frontend interface, state and services
src-tauri/            # Tauri app, commands and native services
  src/tests/          # Application backend tests
  src/services/       # Instances, downloads, Java, launcher, authentication
crates/               # Internal crates of the Rust workspace
  <crate>/src/tests/  # Unit tests per crate
tests/frontend/       # Frontend tests
static/               # Static assets
dist/                 # Packaging for distributions
.github/              # CI and publishing workflows
```

## Процесс запуска

1. Интерфейс вызывает команду `launch`.
2. Сервис `Launcher` блокирует файлы инстанса и устанавливает статус `Starting`.
3. Проверяются зависимости версии; если чего-то не хватает, они ставятся в очередь в `DownloadQueue` и возвращается `VersionNotFound`.
4. `aqua` скачивает версию, загрузчик и JRE по мере необходимости.
5. `zellkern` разрешает наследование манифеста (Vanilla → загрузчик) и формирует аргументы.
6. Токен учётной записи обновляется, и собирается `LaunchConfig` с ОЗУ, аргументами JVM, переменными среды, аутентификацией и Quick Play.
7. `launchwerk` распаковывает нативные библиотеки и запускает процесс Java; stdout/stderr передаются в журналы и интерфейс.
8. По завершении статус возвращается в `Off`. Если процесс завершается с ненулевым кодом и не был остановлен из лаунчера, фиксируется сбой и снимок журнала сохраняется на один час.

## События и IPC

- Команды экспортируются из `src-tauri/src/commands/`.
- События публикуются в шине приложения как `app-event` и обрабатываются во фронтенде.
- Загрузки отдельно сообщают о прогрессе, завершении и ошибках.
- Консоль объединяет текущие строки, историю по инстансам и снимки при сбоях.

## Данные на диске

По умолчанию всё находится в `~/.cubic/`:

- `instances/<name>/` — данные каждого инстанса и его файл `instance.cub`.
- `shared/` — `versions`, `libraries`, `assets`, `natives` и `runtimes`.
- `settings/settings.cub` — настройки, учётные записи и предпочтения.
- `themes/` — темы, установленные пользователем.
- `skins/` — хранилище скинов.

Пути `instances` и `shared` можно изменить в разделе **Настройки → Хранилище**. Конфигурация этих путей хранится в `settings.cub`.

## Обновления

Обновление Tauri обращается к конечным точкам проекта в соответствии с выбранным каналом:

- **Стабильный** — опубликованные выпуски.
- **Предварительный** — версии alpha, beta или rc.

Каждый push в `develop` создаёт артефакты CI, но не публичный выпуск. Публикация следует процессу [Версионирование и релизы](/docs/ru-RU/Advanced/versioning).
