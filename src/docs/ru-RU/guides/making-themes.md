# Как создавать темы для CubicLauncher

CubicLauncher позволяет настраивать пользовательский интерфейс с помощью **тем**. Тема определяет цвета, шрифты, границы, тени, фоновые изображения, иконки, а в формате V2 — ещё и дополнительные таблицы стилей CSS.

В этом руководстве описано, как создать тему с нуля, как упаковать её, как протестировать локально и как опубликовать в официальном репозитории.

## Введение
### Что такое тема?

Тема — это набор файлов, которые CubicLauncher интерпретирует для изменения визуального облика приложения. Внутри CubicLauncher преобразует любой формат темы в общую структуру под названием `ThemeResponse`, которую фронтенд использует для применения стилей.

### Версии формата

CubicLauncher поддерживает две версии формата тем:

| Версия | Формат | Статус | Рекомендация |
|---|---|---|---|
| V1 | JSON (`theme.json`) | Устаревший | Сохранён для совместимости, но не получает новых возможностей. |
| V2 | TOML (`Meta.toml` + `Definition.toml`) | Актуальный | Рекомендуется для новых тем. Поддерживает иконки, внедряемый CSS и более понятную организацию. |


## Общие понятия
### Определение версии

CubicLauncher автоматически определяет версию темы по файлу, присутствующему в каталоге темы:

- Если существует `Meta.toml`, это **V2**.
- Если существует `theme.json`, это **V1**.

При импорте ZIP через `import_theme_zip` CubicLauncher сначала ищет `theme.json` внутри пакета. Если он не найден, лаунчер пытается импортировать файл как пакет V2 (`Meta.toml`).

### Разрешение путей

Относительные пути, указанные для фоновых изображений, шрифтов и иконок, автоматически разрешаются относительно каталога установленной темы. Рекомендуется использовать относительные пути внутри ZIP, чтобы пакет оставался переносимым.

### Проверки ресурсов

CubicLauncher применяет следующие проверки безопасности:

- **Фоновые изображения**: должны быть корректными файлами изображений (определяемыми по сигнатуре) и не могут превышать **25 МБ**.
- **Пользовательские иконки (V2)**: должны иметь расширение `svg`, `png`, `webp`, `jpg` или `jpeg`; растровые изображения не могут превышать **2 МБ**.
- **Шрифты**: если путь относительный, он разрешается локально относительно каталога темы.


## Создание темы V1 (устаревший формат)
Формат V1 использует единственный JSON-файл с именем `theme.json`. Он прост, но ограничен: в нём нет поддержки пользовательских иконок и внедряемого CSS.

:::warning Устаревший формат не принимается в репозитории
Официальный репозиторий Themes больше не принимает заявки в устаревшем формате V1 (`theme.json`). Этот формат сохранён только для совместимости в лаунчере. Для создания и публикации новых тем используйте формат V2 на TOML: `Meta.toml` + `Definition.toml`.
:::

### Обязательные файлы

```
ThemeName/
└── theme.json        # required
```

### Необязательные ресурсы

- `bg.EXT` — фоновое изображение.
- Файлы шрифтов, на которые ссылается `fonts`.

### Схема `theme.json`

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `name` | string | Да | Название темы. |
| `author` | string | Нет | Автор темы. |
| `version` | string | Нет | Версия темы (рекомендуется semver). |
| `type` | string | Нет | Тип темы. Передаётся как есть в листинге. |
| `variables` | object | Да | Карта CSS-переменных `key: value`. |
| `bg_image` | string | Нет | Путь к фоновому изображению. |
| `bg_image_blur` | string | Нет | Размытие фонового изображения. Преобразуется в число, если возможно. |
| `bg_image_opacity` | number | Нет | Непрозрачность фонового изображения (от 0.0 до 1.0). |
| `fonts` | array | Нет | Список пользовательских шрифтов. |

### Шрифты в V1

Каждый элемент массива `fonts` соответствует следующей схеме:

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `family` | string | Да | Название семейства шрифтов. |
| `src` | string | Да | Путь к файлу шрифта. |
| `format` | string | Нет | Формат шрифта, например `woff2`. |
| `weight` | string | Нет | Насыщенность шрифта, например `400` или `700`. |
| `style` | string | Нет | Стиль шрифта, например `normal` или `italic`. |

### Полный пример V1

```json
{
  "name": "Midnight Blue",
  "author": "CubicLabs",
  "version": "1.0.0",
  "type": "user",
  "variables": {
    "--bg-main": "#0a0e17",
    "--bg-card": "#111827",
    "--accent": "#3b82f6",
    "--text-primary": "#e5e7eb",
    "--border-radius": "8px"
  },
  "bg_image": "bg.webp",
  "bg_image_blur": "8",
  "bg_image_opacity": 0.4,
  "fonts": [
    {
      "family": "Inter",
      "src": "fonts/Inter.woff2",
      "format": "woff2",
      "weight": "400"
    }
  ]
}
```

### Ограничения V1

- Нет системы пользовательских иконок.
- Не позволяет внедрять дополнительный CSS.
- Поле `bg_image_blur` принимается как `string` и преобразуется в число.
- CSS-переменные определяются вручную ровно в том виде, в каком они будут применены.


## Создание темы V2 (рекомендуется)
Формат V2 разделяет метаданные и визуальные определения на два файла TOML:

- `Meta.toml`: информация об авторе, название, версия и признак того, внедряет ли тема CSS.
- `Definition.toml`: все визуальные переменные, шрифты, иконки, фоны и дополнительные значения.

### Обязательные файлы

```
ThemeName/
├── Meta.toml           # metadata
└── Definition.toml     # visual definitions
```

### Необязательные ресурсы

- `Inject.css` — дополнительная таблица стилей.
- `bg.EXT` — фоновое изображение.
- Файлы шрифтов.
- Иконки SVG/PNG/WEBP/JPG, организованные в подпапках.

### Схема `Meta.toml`

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `name` | string | Да | Название темы. |
| `author` | string | Нет | Автор темы. |
| `version` | string | Нет | Версия темы (рекомендуется semver). |
| `description` | string | Нет | Краткое описание темы. |
| `injects_css` | boolean | Нет | Указывает, включает ли тема файл `Inject.css`. |

### Схема `Definition.toml`

| Поле | Тип | Описание |
|---|---|---|
| `[background]` | section | Конфигурация фонового изображения. |
| `[background.reference_path]` | string | Путь к фоновому изображению. |
| `[background.image_blur]` | number | Размытие изображения. |
| `[background.image_opacity]` | number | Непрозрачность изображения (от 0.0 до 1.0). |
| `[colors]` | object | Цвета темы. |
| `[text]` | object | Цвета и стили текста. |
| `[borders]` | object | Границы и радиусы. |
| `[layout]` | object | Отступы, ширины, высоты и другие параметры макета. |
| `[shadows]` | object | Тени и свечения. |
| `[backgrounds]` | object | Дополнительные цвета фона. |
| `[backdrop]` | object | Значения размытия подложки в пикселях. |
| `[fonts]` | array | Пользовательские шрифты. |
| `[icons]` | section | Пользовательские иконки. |
| `[icons.preview]` | string | Иконка предпросмотра темы. |
| `[icons.<group>]` | object | Иконки, сгруппированные по категориям. |
| `[others]` | object | Произвольные дополнительные переменные. |

### Система префиксов CSS-переменных

В V2 CubicLauncher автоматически преобразует секции TOML в плоские CSS-переменные, которые может использовать фронтенд. В следующей таблице показан префикс, применяемый к каждой секции:

| Секция | Пример ключа | Сгенерированная переменная |
|---|---|---|
| `colors` | `accent` | `--accent` |
| `text` | `primary` | `--text-primary` |
| `borders` | `radius` | `--border-radius` |
| `layout` | `spacing` | `--spacing` |
| `shadows` | `glow-accent` | `--glow-accent` |
| `backgrounds` | `card` | `--bg-card` |
| `backdrop` | `modal` | `--backdrop-blur-modal` |
| `others` | `icon-filter` | `--icon-filter` |

Важные замечания:

- Поле `[background]` **не преобразуется в CSS-переменные**. Оно передаётся напрямую как фоновое изображение темы.
- Дублирующиеся ключи вызывают предупреждение в журналах и перезаписываются.

:::warning Секции на верхнем уровне, без префикса `theme.`
В `Definition.toml` секции располагаются на верхнем уровне и **без** префикса `theme.`: `[background]`, `[colors]`, `[text]`, `[borders]`, `[layout]`, `[shadows]`, `[backgrounds]`, `[backdrop]`, `[others]`, `[[fonts]]`, `[icons]`. Если написать `[theme.colors]`, `[[theme.fonts]]` и т. п., CubicLauncher проигнорирует **весь** файл, не выдав ошибки: тема импортируется, но ничего не применяет.

Аналогично, `Meta.toml` определяет свои поля на верхнем уровне (`name`, `author`, `version`, `description`, `injects_css`), а **не** внутри секции `[meta]`.
:::

### Минимальный пример V2

`Meta.toml`:

```toml
name = "Minimal"
author = "CubicLabs"
version = "1.0.0"
```

`Definition.toml`:

```toml
[background]

[colors]
accent = "#ffffff"
bg-main = "#0a0a0a"

[text]
primary = "#e5e5e5"
```

### Полный пример V2

`Meta.toml`:

```toml
name = "Midnight Blue"
author = "CubicLabs"
version = "2.0.0"
description = "A dark theme with blue accents."
injects_css = true
```

`Definition.toml`:

```toml
[background]
```

```css

.market-item {
```

## Размеры интерфейса и стили
Изменение `5a7e752` расширяет возможности настройки через CSS-переменные, не меняя форматов файлов. Темы V1 могут использовать эти переменные в `variables`; темы V2 объявляют их в категориях `Definition.toml`. Если переменная не указана, сохраняется значение лаунчера по умолчанию.

### Списки и сетка Маркета

| Переменная | Значение по умолчанию | Использование |
|---|---|---|
| `--sidebar-width` / `--sidebar-compact-width` | `260px` / `70px` | Ширина обычной / компактной боковой панели. |
| `--sidebar-row-height` / `--sidebar-compact-row-height` | `52px` / `50px` | Высота строки инстанса в каждом режиме. |
| `--sidebar-row-gap` | `8px` | Отступ между строками боковой панели. |
| `--version-row-height` | `78px` | Высота строки в селекторе загрузки версии. |
| `--resource-row-height` / `--resource-row-gap` | `130px` / `6px` | Общая высота строки и отступ в каталогах модов и наборов ресурсов. |
| `--resource-card-padding` / `--resource-icon-size` | `14px 16px` / `56px` | Внутренний отступ карточки и размер иконки. |
| `--market-row-height` / `--market-grid-gap` | `224px` / `12px` | Общая высота строки и отступ в Маркете. |
| `--market-card-min-width` | `280px` | Опорная ширина для расчёта колонок Маркета (от 1 до 4). |
| `--market-grid-padding` | `8px` | Пространство справа от строк Маркета. |
| `--market-card-padding` / `--market-icon-size` | `14px` / `48px` | Внутренний отступ карточки Маркета и размер иконки. |

Виртуализированные списки отрисовывают только видимые элементы. Используйте эти переменные для изменения их размеров: изменение только CSS `height` или отступов карточки может рассинхронизировать расчёты прокрутки. В Маркете видимая высота строки равна `--market-row-height` минус `--market-grid-gap`; у карточек ресурсов из общей высоты вычитается `--resource-row-gap`.

Размеры вычисляются средствами CSS и отслеживаются через `ResizeObserver`: поддерживаются `px`, `rem`, `calc()` и `var()`, а значения обновляются при изменении размера шрифта или загрузке `Inject.css`. Для высот и ширин используйте положительные длины; отступ сетки и внутренний отступ Маркета могут быть `0px`. Увеличивая внутренние отступы, иконки или размер текста, корректируйте общую высоту.

### Цвета, состояния и эффекты

| Переменные | Использование и примечательные значения по умолчанию |
|---|---|
| `--accent-text` | Текст на акцентных кнопках; `#0a0a0a`. Изменяйте вместе с `--accent`, чтобы сохранить контраст. |
| `--surface-rgb`, `--surface-subtle`, `--surface-raised` | Базовый RGB (`255, 255, 255`) и поверхности с непрозрачностью `0.02` / `0.04`. Светлые темы могут использовать тёмную базу. |
| `--border-hover`, `--border-focus` | Границы взаимодействия, производные от `--surface-rgb`, с непрозрачностью `0.1` / `0.3`. |
| `--color-success`, `--color-error`, `--color-warning`, `--color-info` | Семантические цвета: `#22c55e`, `#ef4444`, `#eab308`, `#60a5fa`. |
| `--color-on-success`, `--color-on-error`, `--color-on-warning`, `--color-on-info` | Текст на фонах статусов; `#fff`. |
| `--color-status-starting`, `--color-status-started` | Статус запуска / работы; используйте `--color-info` / `--color-success`. |
| `--toast-bg`, `--toast-border` | Фон и граница уведомлений; производные от `--bg-card` и `--surface-rgb`. |
| `--download-library`, `--download-asset`, `--download-native`, `--download-client` | Цвета библиотек, ресурсов, нативных компонентов и клиента: `#4ade80`, `#60a5fa`, `#f59e0b`, `#a78bfa`. |
| `--download-verifying`, `--download-generic`, `--download-processing`, `--download-jre` | Проверка, обычная загрузка, обработка и Java: `#f472b6`, `#94a3b8`, `#fb923c`, `#22d3ee`. |
| `--log-trace`, `--log-debug`, `--log-info`, `--log-message`, `--log-warn`, `--log-error`, `--log-fatal`, `--log-launcher`, `--log-stderr`, `--log-unknown` | Цвета по уровню/источнику журнала; по умолчанию производятся от цветов текста и статусов. |
| `--media-overlay`, `--media-overlay-text`, `--viewer-overlay` | Оверлей изображения (`rgba(0, 0, 0, 0.6)`), текст (`#fff`) и просмотрщик (`rgba(0, 0, 0, 0.9)`). |
| `--shadow-inset`, `--shadow-floating`, `--shadow-image`, `--shadow-indicator` | Внутренняя, плавающая тень, тень изображения и индикатора. Последние три используют `--shadow-lg`, `--shadow-md` и `--shadow-sm`. |
| `--shadow-drawer-left`, `--shadow-drawer-right`, `--shadow-drawer-top`, `--shadow-drawer-bottom` | Тени выдвижных панелей по направлению. |
| `--bg-image-brightness`, `--bg-image-size`, `--bg-image-position` | Яркость фона (`0.4`), размер (`cover`) и положение (`center`). Яркость не зависит от непрозрачности и размытия, заданных в `[background]`. |

Переменные `--error` и `--warning` остаются как устаревшие имена. Для новых тем предпочитайте семантические цвета `--color-*`. Если вы меняете `--accent`, `--color-success`, `--color-error` или `--color-warning`, сохраняйте согласованность их переменных `*-rgb`, когда они используются для прозрачности; записывайте значения RGB как `"239, 68, 68"`, без `rgb()`.

### Пример V2: размеры и контраст

Этот `Definition.toml` можно использовать с приведённым ранее минимальным `Meta.toml`. Адаптируя его к существующей теме, объедините ключи в соответствующие секции: не повторяйте таблицу TOML.

```toml
[background]

[colors]
accent = "#d89b53"
accent-rgb = "216, 155, 83"
accent-hover = "#e5ad6d"
accent-text = "#17120d"
bg-main = "#17120d"
bg-sidebar = "#211a13"
bg-card = "#292017"
surface-rgb = "255, 240, 220"
log-warn = "#f1c875"
download-jre = "#8dcbb8"

[text]
primary = "#f5eadb"
secondary = "#c6b6a1"

[layout]
font-size-base = "14px"
sidebar-row-height = "4rem"
sidebar-compact-row-height = "4rem"
version-row-height = "6rem"
resource-row-height = "10rem"
resource-card-padding = "16px"
market-row-height = "calc(18rem + 12px)"
market-grid-gap = "12px"
market-card-min-width = "300px"
market-card-padding = "20px"
modal-width = "480px"
modal-padding = "24px"
icon-scale = "1.1"

[others]
font-family-mono = "ui-monospace, Consolas, monospace"
bg-image-brightness = "0.55"
```

Значения переменных — строки, включая безразмерные коэффициенты, такие как `icon-scale`. Используйте `[layout]`, чтобы получить `--modal-width` или `--font-size-base`, и `[others]` для `--font-family-mono`. Если поместить `font-family-mono` в `[text]`, будет создана переменная `--text-font-family-mono`, которая не управляет моноширинным шрифтом.


## Дополнительные ресурсы
### Фоновое изображение

Фоновое изображение настраивается по-разному в зависимости от версии:

- **V1**: `bg_image`, `bg_image_blur`, `bg_image_opacity`.
- **V2**: секция `[background]` с `reference_path`, `image_blur`, `image_opacity`.

Поддерживаемые форматы: **PNG, WEBP, JPG, JPEG и GIF** (внутренняя проверка использует `infer`, но для избежания проблем рекомендуются PNG, WEBP или JPG).

Если изображение превышает **25 МБ** или не распознаётся как корректное, CubicLauncher игнорирует его и в V1 записывает предупреждение в журнал.

### Настройка боковой панели

Боковая панель CubicLauncher стилизуется в основном через CSS-переменные. Следующие переменные управляют её внешним видом:

| Переменная | Описание |
|---|---|
| `--bg-sidebar` | Сплошной цвет фона боковой панели. |
| `--bg-sidebar-gradient` | Градиент, накладываемый поверх фона. Если задан, имеет приоритет над `--bg-sidebar`. |
| `--sidebar-width` | Ширина боковой панели в обычном режиме. |
| `--bg-item-active` | Фон активного или выбранного элемента боковой панели. |
| `--text-primary` | Основной цвет текста боковой панели. |
| `--text-secondary` | Вторичный цвет текста. |
| `--accent` | Акцентный цвет для кнопок и интерактивных состояний. |
| `--border-color` | Цвет границ и разделителей. |

#### Поведение градиента

Во фронтенде боковая панель использует следующее правило:

```css
background: var(--bg-sidebar-gradient, var(--bg-sidebar));
```

Это означает, что если `--bg-sidebar-gradient` задан, будет применён градиент. Если он не задан, в качестве запасного сплошного цвета используется `--bg-sidebar`.

#### Обычный и компактный режимы

Боковую панель можно переключать между двумя режимами из интерфейса:

- **Обычный режим**: использует ширину, заданную `--sidebar-width` (значение по умолчанию: `260px`).
- **Компактный режим**: сохраняет те же цвета и градиенты, но отображает только иконки. Его ширина управляется `--sidebar-compact-width` (по умолчанию `70px`).

#### Пример V1

```json
"variables": {
  "--bg-sidebar": "#0f1010",
  "--bg-sidebar-gradient": "linear-gradient(180deg, #1a1a2e 0%, #0f1010 100%)",
  "--sidebar-width": "260px",
  "--bg-item-active": "#1c1d1d",
  "--text-primary": "#d8d8d8",
  "--accent": "#3b82f6"
}
```

#### Пример V2

```toml
[colors]
bg-sidebar = "#0f1010"
bg-sidebar-gradient = "linear-gradient(180deg, #1a1a2e 0%, #0f1010 100%)"
bg-item-active = "#1c1d1d"
accent = "#3b82f6"

[layout]
sidebar-width = "260px"

[text]
primary = "#d8d8d8"
```

> В V2 ключи в секции `colors` напрямую порождают переменные с префиксом `--` (`bg-sidebar` → `--bg-sidebar`), а ключи в `layout` также порождают переменные с префиксом `--` (`sidebar-width` → `--sidebar-width`).

### Настройка модальных окон

Модальные окна CubicLauncher используют сочетание глобальных переменных для определения оверлея, размытия и тела диалога.

| Переменная | Описание |
|---|---|
| `--bg-overlay` | Цвет или фон тёмного оверлея, закрывающего экран за модальным окном. |
| `--backdrop-blur-modal` | Величина размытия, применяемого к оверлею модального окна. |
| `--bg-sidebar` | Цвет фона тела модального окна. CubicLauncher повторно использует этот цвет для сохранения визуальной согласованности. |
| `--border` / `--border-color` | Цвет границы модального окна. |
| `--border-radius` | Радиус границы модального окна. |
| `--shadow-lg` | Тень модального окна. |
| `--text-primary` | Цвет заголовка и основного текста модального окна. |
| `--text-muted` | Цвет вторичных кнопок и вспомогательного текста. |
| `--modal-width` | Желаемая ширина, ограниченная `90vw`. Если не указана, используется ширина компонента (`400px`, если ничего не задано). |
| `--modal-max-height` | Максимальная высота; по умолчанию `90vh`. |
| `--modal-padding` / `--modal-gap` | Внутренний отступ содержимого и интервал; по умолчанию `var(--space-xl)` (`24px`) / `20px`. |
| `--modal-title-size` / `--modal-footer-gap` | Размер заголовка и интервал действий; `1rem` / `10px`. |
| `--drawer-width` / `--drawer-max-height` | Ширина боковой выдвижной панели (`340px`, ограничена `90vw`) и максимальная высота верхней/нижней панели (`85vh`). |

#### Поведение оверлея

Во фронтенде оверлей модального окна определяется следующим образом:

```css
background: var(--bg-overlay, rgba(0, 0, 0, 0.75));
backdrop-filter: blur(var(--backdrop-blur-modal, 4px));
```

Базовый CSS уже определяет `--bg-overlay` как `rgba(0, 0, 0, 0.7)`, а `--backdrop-blur-modal` как `4px`. Значение `0.75` в этом правиле — лишь запасной вариант, если переменная недоступна, а не базовое значение лаунчера.

#### Примечание о фоне модального окна

Тело модального окна использует `--bg-sidebar` в качестве цвета фона:

```css
.modal {
  background: var(--bg-sidebar);
}
```

Это означает, что настройка `--bg-sidebar` также меняет внешний вид модальных окон. Если вам нужен отдельный фон исключительно для модальных окон, его можно переопределить с помощью `Inject.css`, используя селектор вроде `.modal`.

#### Пример V1

```json
"variables": {
  "--bg-overlay": "rgba(0, 0, 0, 0.85)",
  "--backdrop-blur-modal": "6px",
  "--bg-sidebar": "#141414",
  "--border-color": "#2a2a2a",
  "--border-radius": "12px",
  "--shadow-lg": "0 8px 28px rgba(0, 0, 0, 0.6)",
  "--text-primary": "#e5e5e5",
  "--text-muted": "#888888"
}
```

#### Пример V2

```toml
[colors]
bg-overlay = "rgba(0, 0, 0, 0.85)"
bg-sidebar = "#141414"

[borders]
color = "#2a2a2a"
radius = "12px"

[backdrop]
modal = 6.0

[shadows]
shadow-lg = "0 8px 28px rgba(0, 0, 0, 0.6)"

[text]
primary = "#e5e5e5"
muted = "#888888"
```

### Настройка полос прокрутки

CubicLauncher стилизует полосы прокрутки через CSS-переменные, которые затем применяются селекторами `::-webkit-scrollbar`.

| Переменная | Описание |
|---|---|
| `--scrollbar-track` | Фон дорожки полосы прокрутки. |
| `--scrollbar-thumb` | Цвет бегунка полосы прокрутки. |
| `--scrollbar-thumb-hover` | Цвет бегунка при наведении. |
| `--scrollbar-size` | Ширина и высота полосы прокрутки; по умолчанию `6px`. |
| `--scrollbar-radius` | Радиус бегунка; по умолчанию `10px`. |

#### Поведение

Базовый файл использует:

```css
::-webkit-scrollbar-track {
  background: var(--scrollbar-track, transparent);
}

::-webkit-scrollbar-thumb {
  background: var(--scrollbar-thumb, var(--border));
  border-radius: var(--scrollbar-radius);
}

::-webkit-scrollbar-thumb:hover {
  background: var(--scrollbar-thumb-hover, var(--text-secondary));
}
```

Базовый CSS определяет дорожку как `var(--bg-main)`, бегунок как `rgba(var(--surface-rgb), 0.12)`, а состояние наведения как `var(--text-secondary)`. Вторые аргументы `var()` — запасные значения, если эти переменные недоступны.

#### Примечание о внутренних полосах прокрутки

Внутренние полосы прокрутки `.qm-scroll` и `.modal` также используют `--scrollbar-size`, `--scrollbar-thumb` и `--scrollbar-radius`. Некоторые детали остаются локальными, например прозрачная дорожка в `.qm-scroll`; их можно настроить через `Inject.css`.

#### Пример V1

```json
"variables": {
  "--scrollbar-track": "#0c0c0c",
  "--scrollbar-thumb": "#333333",
  "--scrollbar-thumb-hover": "#555555"
}
```

#### Пример V2

```toml
[colors]
scrollbar-track = "#0c0c0c"
scrollbar-thumb = "#333333"
scrollbar-thumb-hover = "#555555"
```

### Настройка типографики

Базовую типографику и элементы управления можно настроить следующими переменными:

| Переменная | Описание |
|---|---|
| `--font-family` | Основной шрифт, используемый во всём интерфейсе. |
| `--font-size-base` | Базовый размер шрифта (`14px`); влияет на размеры, выраженные в `rem`. |
| `--font-family-mono` | Моноширинный шрифт для журналов и технического содержимого; по умолчанию используется системный набор шрифтов. |
| `--font-size-sm` / `--font-size-lg` | Малый / большой размеры; `0.8rem` / `1.2rem`. |
| `--font-size-control` / `--font-size-label` | Размер элемента управления / подписи; `0.85rem` / `0.65rem`. |
| `--font-weight-normal` / `--font-weight-medium` / `--font-weight-bold` | Насыщенность текста; `400` / `600` / `700`. |
| `--line-height` | Базовая высота строки; `1.5`. |
| `--log-font-size` / `--log-line-height` | Размер шрифта и высота строки журнала; `0.75rem` / `var(--line-height)`. |
| `--log-line-padding` / `--log-line-min-height` | Внутренний отступ и минимальная высота строки журнала; `2px 14px` / `22px`. |
| `--control-padding` / `--button-padding` | Внутренний отступ элемента управления / кнопки; `10px 12px` / `8px 16px`. |
| `--icon-scale` | Коэффициент масштабирования иконок, использующих общий компонент `Icon`; `1`. |
| `--font-loaded` | Внутренний флаг, указывающий, загружен ли пользовательский шрифт. Обычно изменять его не требуется. |

#### Поведение

Базовый CSS определяет:

```css
html {
  font-size: var(--font-size-base, 14px);
}

body {
  font-family: var(--font-family);
}
```

Это означает, что изменение `--font-size-base` пропорционально влияет на весь текст, использующий единицы `rem`, а изменение `--font-family` влияет на весь интерфейс.

#### Использование пользовательского шрифта

Чтобы `--font-family` работал корректно, файлы шрифтов должны быть включены в тему и объявлены в секции `fonts`. Семейство, объявленное в `fonts`, должно совпадать со значением `--font-family`.

Если у шрифта несколько начертаний или стилей, объявляйте каждый вариант отдельно.

#### Пример V1

```json
{
  "variables": {
    "--font-family": "\"Inter\", system-ui, sans-serif",
    "--font-size-base": "14px"
  },
  "fonts": [
    {
      "family": "Inter",
      "src": "fonts/Inter-Regular.woff2",
      "format": "woff2",
      "weight": "400"
    },
    {
      "family": "Inter",
      "src": "fonts/Inter-Bold.woff2",
      "format": "woff2",
      "weight": "700"
    }
  ]
}
```

#### Пример V2

```toml
name = "Custom Typography"
author = "CubicLabs"
version = "1.0.0"
```

`Definition.toml`:

```toml
[background]

[others]
font-family = "\"Inter\", system-ui, sans-serif"

[layout]
font-size-base = "14px"

[[fonts]]
family = "Inter"
src = "fonts/Inter-Regular.woff2"
format = "woff2"
weight = "400"

[[fonts]]
family = "Inter"
src = "fonts/Inter-Bold.woff2"
format = "woff2"
weight = "700"
```

> В V2 переменные `--font-family` и `--font-size-base` не относятся к какой-либо конкретной семантической категории. Рекомендуется определять `--font-family` в `[others]`, а `--font-size-base` в `[layout]`.

### Пользовательские шрифты

И V1, и V2 позволяют использовать пользовательские шрифты по следующей схеме:

```toml
[[fonts]]
family = "Inter"
src = "fonts/Inter.woff2"
format = "woff2"
weight = "400"
style = "normal"
```

| Поле | Описание |
|---|---|
| `family` | Название семейства шрифтов. |
| `src` | Путь к файлу шрифта. Может быть относительным к теме, абсолютным или начинаться с `file:`. |
| `format` | Формат шрифта (`woff2`, `ttf` и т. д.). |
| `weight` | Насыщенность шрифта (`100`–`900`, `bold` и т. д.). |
| `style` | Стиль (`normal`, `italic` и т. д.). |

### Пользовательские иконки (только V2)

V2 позволяет заменять иконки фронтенда через секцию `[icons]`.

Структура выглядит следующим образом:

```toml
[icons]
preview = "icons/preview.png"

[icons.ui]
play = "icons/ui/play.svg"
settings = "icons/ui/settings.svg"
```

| Поле | Описание |
|---|---|
| `preview` | Путь к иконке, отображаемой как предпросмотр темы в листинге. |
| `[icons.<group>]` | Группы иконок. Каждый ключ внутри группы передаётся фронтенду как `{group}:{name}`. |

Пример: ключ `play` внутри группы `ui` передаётся как `ui:play`.

Ограничения:

- Допустимые расширения: `svg`, `png`, `webp`, `jpg`, `jpeg`.
- Растровые изображения: максимум **2 МБ**.
- Файл проверяется как корректное изображение (PNG/WEBP/JPG) или проверяется на существование (SVG).

Некорректные иконки молча удаляются с предупреждением в журналах.

### Внедрённый CSS (только V2)

V2 позволяет включить дополнительную таблицу стилей с именем `Inject.css` в корне темы.

Чтобы указать, что тема включает пользовательский CSS, задайте `injects_css = true` в `Meta.toml`:

```toml
name = "Advanced Theme"
injects_css = true
```

Содержимое `Inject.css` читается и передаётся фронтенду в поле `inject_css` структуры `ThemeResponse`, а лаунчер применяет его при активации темы.

Начиная с `5a7e752`, глобальные стили и ограниченные стили Svelte сгруппированы в `@layer cubic`. Обычные правила `Inject.css` **вне любого слоя** имеют приоритет над обычными правилами в этом слое, не требуя сгенерированных классов Svelte или `!important`:

```css
/* Inject.css: keep these rules outside @layer cubic */
.market-item {
  padding: 20px;
}

.modal {
  background: var(--bg-card);
}

/* Dimensions inherited by the grid and its observers */
.market-grid {
  --market-row-height: calc(18rem + 12px);
  --market-grid-gap: 12px;
}
```

Приоритет слоёв не переопределяет правила для встроенных стилей или объявлений `!important`. Предпочитайте определять глобальные переменные в `Definition.toml`; при использовании CSS применяйте их к контейнеру, который их использует, например к `.market-grid`. Не переопределяйте вычисляемые внутренние значения (`--row-height`, `--columns` или высоты и трансформации виртуализированных строк).

При возврате к встроенной теме убедитесь, что внедрённые правила исчезают, а размеры по умолчанию восстанавливаются.


## Упаковка темы
Тема распространяется в виде ZIP-файла. Внутри ZIP файлы должны находиться в корневой папке с именем темы.

### Структура ZIP для V2

```
Author_Theme.zip
└── ThemeName/
    ├── Meta.toml
    ├── Definition.toml
    ├── Inject.css            (optional)
    ├── bg.webp               (optional)
    ├── fonts/
    │   └── Inter.woff2
    └── icons/
        ├── preview.png
        └── ui/
            ├── play.svg
            └── settings.svg
```

### Структура ZIP для V1

```
Author_Theme.zip
└── ThemeName/
    ├── theme.json
    ├── bg.webp               (optional)
    └── fonts/
        └── Inter.woff2
```

### Правила ZIP

- ZIP может содержать целевой файл в корне (`theme.json` или `Meta.toml`) либо внутри подпапки.
- Если обнаружено несколько целевых файлов или несколько подпапок с ними, импорт отклоняется.
- Имя ZIP-файла для публикации в официальном репозитории должно соответствовать шаблону `Author_Theme.zip`.


## Локальное тестирование темы
CubicLauncher предоставляет несколько команд для импорта тем. Во время разработки можно использовать любой из следующих способов:

### Импорт файла V1 JSON напрямую

Используйте команду `import_theme` и выберите файл `theme.json`.

### Импорт ZIP V1 или V2

Используйте команду `import_theme_zip`. CubicLauncher попытается автоматически определить, что это — V1 (`theme.json`) или V2 (`Meta.toml`).

### Импорт пакета V2 напрямую

Используйте команду `import_theme_cbth` для файлов `.cbth` (формат пакета V2).

### Расположение установленных тем

Команда `get_themes_dir_path` возвращает путь, по которому CubicLauncher хранит установленные темы. Во время разработки можно проверить эту папку, чтобы убедиться, что файлы извлечены правильно.

### Проверка новых настроек

1. Используйте сборку, включающую `5a7e752`, импортируйте тему и активируйте её.
2. Проверьте контраст на кнопках с помощью `--accent-text`, а также в уведомлениях, журналах, загрузках и оверлеях.
3. Изменяйте высоты строк боковой панели, версий и ресурсов, а также размеры `--market-*` при прокрутке. Проверьте наличие перекрытий или зазоров; повторите с `rem` и другим `--font-size-base`.
4. В V2 попробуйте `.market-item { padding: 20px; }` в `Inject.css` без `!important` и убедитесь, что правило применяется. Увеличьте высоту строки, если содержимому нужно больше места.
5. Проверьте модальные окна, иконки, моноширинные шрифты и яркость фона, в том числе при отключённых размытии и анимациях в лаунчере.
6. Вернитесь к встроенной теме и убедитесь, что стили и размеры восстановились; переключайтесь между двумя темами, чтобы обнаружить оставшиеся значения.


## Публикация темы
Хотите поделиться своей темой с сообществом? Откройте Pull Request в [официальный репозиторий Themes](https://github.com/CubicLauncherDevs/Themes). Опубликованные темы появляются на официальном сайте: [cubiclauncher.org/themes](https://www.cubiclauncher.org/themes).

### Структура репозитория

Каждая тема находится в `src/<Author>/<Theme>/`, с `theme.md` в корне темы и подпапкой для каждой версии (`V1`, `V2`, …):

> `V1/`, `V2/`, … — это **папки версий внутри репозитория**, а не устаревший формат V1 CubicLauncher. Внутри каждой папки версии вы размещаете файлы темы в любом предпочитаемом формате (рекомендуется V2).

```
src/
  <Author>/
    <Theme>/
      theme.md               # theme description (required)
      vflag.txt              # theme verification, staff only (optional)
      V1/
        Meta.toml            # metadata
        Definition.toml      # visual definitions
        bg.png               # background image
        fonts/               # custom fonts
          Font.ttf
        Showcase.png         # preview (optional)
        changelog.md         # version changes (optional)
      V2/                    # new versions (optional)
        ...
```

:::info Бинарные файлы
Бинарные файлы (изображения, шрифты) **не хранятся в Git**. Рабочий процесс CI автоматически загружает их в Cloudflare R2, а затем удаляет из репозитория. Поэтому в репозитории остаются только текстовые файлы: TOML, CSS, TXT, MD и т. д.
:::

### Шаги для добавления темы

1. Создайте `src/YourAuthor/YourTheme/theme.md` с описанием темы.
2. Создайте папку версии `src/YourAuthor/YourTheme/V1/`.
3. Добавьте `Meta.toml` и `Definition.toml` (формат TOML CubicLauncher).
4. Добавьте `bg.png` (или `.jpg`, `.gif`, `.webp`) в качестве фонового изображения.
5. *(Необязательно)* Добавьте `Showcase.png` как предпросмотр, шрифты в `fonts/`, а также `Inject.css`, `icons/` и т. д.
6. *(Необязательно)* Добавьте `changelog.md` с журналом изменений версии.
7. Чтобы опубликовать новые версии темы, создайте `V2/`, `V3/` и т. д.
8. Откройте Pull Request в репозиторий.

### Файлы темы

**В корне темы:**

| Файл | Обязателен? | Описание |
|---|---|---|
| `theme.md` | **Да** | Описание/README темы в Markdown. |
| `vflag.txt` | Нет | Флаг полной проверки темы. **Добавлять его должен только персонал; если автор включит его, тема не будет проверена.** |

**Внутри каждой папки версии (`V1/`, `V2/`, …):**

| Файл | Обязателен? | Описание |
|---|---|---|
| `Meta.toml` | **Да** | Метаданные темы. |
| `Definition.toml` | **Да** | Визуальные определения темы. |
| `bg.EXT` | **Да** | Фоновое изображение. Форматы: PNG, GIF, WEBP, JPG. |
| `fonts/` | Нет | Пользовательские шрифты. |
| `Inject.css` | Нет | Дополнительный CSS (требует `injects_css = true` в `Meta.toml`). |
| `icons/` | Нет | Пользовательские иконки (только формат V2). |
| `Showcase.png` | Нет | Предпросмотр этой версии (имя *нечувствительно к регистру*). |
| `changelog.md` | Нет | Изменения в этой версии. |

**Пример `theme.md`:**

```markdown
# My Theme

Markdown description of the theme, its inspiration, etc.
```

**Пример `changelog.md`:**

```markdown
# V1

- First release
- Dark theme with green accents
```

### Проверка темы

Каталог `themes.json` помечает тему как `verified: true` только если файл с точным именем `vflag.txt` существует в `src/<Author>/<Theme>/`, рядом с `theme.md`. Он может быть пустым: его содержимое не читается.

> **Важно:** файл `vflag.txt` **должен добавлять только персонал**. Если вы как автор темы включите его в свой PR, ваша тема **не будет проверена**.

Проверка применяется к теме в целом. Каталог с именем `vflag.txt` или файл внутри `V1/`, `V2/` и т. д. не проверяет её. Без этого файла или при его удалении каталог создаётся с `verified: false`.

Добавление или удаление только этого флага обновляет каталог без повторной генерации предпросмотров и без загрузки/удаления ресурсов в R2.

### Как добавить только `Showcase.png` к существующей теме?

1. Добавьте `Showcase.png` в `src/<Author>/<Theme>/V1/Showcase.png`.
2. Закоммитьте и отправьте изменения в `master` (или откройте PR).

Рабочий процесс загружает файл в R2, обновляет `showcaseUrl` и сохраняет существующие URL-адреса R2 для остальных ресурсов (фона, шрифтов и т. д.).

> Предпросмотр генерируется автоматически. Если `bg.png` отсутствует на диске (он уже был загружен в R2 в предыдущем запуске), в качестве запасного варианта для предпросмотра будет использован градиент.

### Что происходит после слияния?

Репозиторий включает рабочий процесс `Generate + Assets to R2` (`.github/workflows/`), который запускается при **push в `master`** и в **PR**, когда изменяются файлы в `src/`:

1. Определяет, какие каталоги версий изменились (например, `src/YourAuthor/YourTheme/V1`).
2. Оптимизирует новые PNG с помощью `oxipng`.
3. Генерирует предпросмотры только для изменённых каталогов (`generate.js --dirs`).
4. Объединяет внешние *коллекции* в `packages.json`.
5. Загружает новые бинарные ресурсы в R2, обновляет `themes.json` URL-адресами R2 и удаляет локальные бинарные файлы (`scripts/upload-assets.mjs`).
6. Коммитит и отправляет изменения (`[skip ci]`, чтобы избежать циклов).

Итоговый `themes.json` отдаётся статически и используется сайтом CubicLauncher для отображения и загрузки тем. Вам не нужно делать ничего дополнительного: как только ваш PR будет принят, тема автоматически появится на [cubiclauncher.org/themes](https://www.cubiclauncher.org/themes).

### Файл Themes Archive

В разделе *Actions* также доступен ручной рабочий процесс **`Themes Archive Release`**. При запуске он создаёт релиз GitHub с именем `archive-YYYY-MM-DD-HHMM`, содержащий ZIP со всеми темами и всеми их версиями:

- Заново собирает полный `src/`, скачивая текстовые файлы из GitHub raw, а бинарные ресурсы из R2.
- Прикрепляет `themes.json`, `packages.json`, `README.md` и `LICENSE`.
- Проверяет, что ZIP не превышает лимит GitHub в 2 ГБ, прежде чем опубликовать его.

### Ресурсы на R2

- Бинарные файлы загружаются на `https://themes.cubiclauncher.org/` с хешированными именами (`file.<hash8>.ext`) и заголовком `Cache-Control: immutable`.
- Текстовые файлы отдаются из GitHub raw.
- В бакете R2 включён CORS, чтобы разрешить загрузку с фронтенда.

```
Example:
  src/4xnl/Jadol/V1/bg.jpg
  → https://themes.cubiclauncher.org/src/4xnl/Jadol/V1/bg.132191b1.jpg
```

### Лицензия репозитория

Репозиторий Themes распространяется по лицензии [CC0 1.0 Universal](https://github.com/CubicLauncherDevs/Themes/blob/master/LICENSE) (общественное достояние). Отправляя свою тему, вы соглашаетесь опубликовать её под этой лицензией. Помните, что **шрифты**, включённые в вашу тему, сохраняют собственную лицензию: приложите её и используйте только те шрифты, которые вы вправе распространять.


## Дизайн тем с помощью ИИ (agents.md)
ИИ может значительно ускорить дизайн тем, но он также склонен воспроизводить шаблонные сочетания: тёмный фон + синий акцент, шрифты Inter и почти ничего больше. Чтобы использовать ИИ, не впадая в повторения, воспользуйтесь этим промптом или адаптируйте его под своего ассистента.

> Этот блок работает как справочник в стиле `agents.md` для ИИ и авторов. Не стесняйтесь скопировать его, вставить в любимый чат и адаптировать под желаемую концепцию.

### Рекомендуемый промпт для ИИ-агентов

Скопируйте и вставьте это в своего ассистента, скорректировав концепцию:

```text
Design a V2 theme for CubicLauncher (`Meta.toml` + `Definition.toml`).

Concept: <describe your idea in one line>.

Rules:
- Palette derived from the theme background, not scattered colors: pick the background first and pull text, borders, and accent from it (same hue, different brightness).
- No default blue/purple or Inter/Roboto fonts. If the concept doesn't call for a color, pick an uncommon one.
- The background needs texture or a subtle gradient, never a flat color.
- Semantic tokens in `[colors]`, `[backgrounds]`, `[text]`, `[borders]`, `[layout]`, `[shadows]`, `[backdrop]`, `[others]`.
- `Inject.css` only if variables aren't enough.
- Sections at the root, without the `theme.` prefix; `Meta.toml` fields at the root, without `[meta]`.
- Relative paths; no `vflag.txt`; background ≤ 25 MB and icons ≤ 2 MB.
- Validate the TOML before delivering.
```

### Как избежать шаблонных результатов

- **Не просите «тёмную тему»**: попросите что-то вроде «интерфейс терминала VT220», «эстетика mall vaporwave», «швейцарский бруталистский дизайн», «интерфейс Pip-Boy», «японская lo-fi эстетика» и т. д.
- **Ограничьте «безопасные» цвета**: если ИИ по умолчанию выбирает синий/зелёный/фиолетовый, попросите заменить акцент на охру, коралловый, приглушённую бирюзу, сероватую лаванду и т. д.
- **Просите намеренные несовершенства**: едва заметный фоновый шум, слегка потёртые края, длинные тени, необычные контрасты.
- **Сделайте типографику частью идентичности**: шрифт с засечками для заголовков в современном лаунчере может запомниться лучше, чем Inter повсюду.
- **Используйте `Inject.css` для визуальных подписей**: градиентные границы, альтернативные углы, стеклянные/нео-эффекты, моноширинный шрифт в отдельных панелях.
- **Проверьте папку `icons/`**: пользовательские иконки — огромный отличительный фактор; если вы не рисуете их вручную, попросите ИИ создать целостный набор и экспортируйте его в SVG.

### Чек-лист перед публикацией

- [ ] У темы есть чёткая концепция, а не просто «тёмная с акцентом».
- [ ] Палитра отличается от популярных тем, таких как Midnight Blue.
- [ ] Шрифты загружаются, читаемость хорошая.
- [ ] У `bg.png` есть детали, текстура или градиент, а не просто сплошной цвет.
- [ ] Иконки (если есть) соответствуют концепции.
- [ ] TOML проходит проверку корректно.
- [ ] Тема не содержит `vflag.txt`.


## Краткий справочник
### Сравнительная таблица V1 и V2

| Возможность | V1 | V2 |
|---|---|---|
| Основной формат | JSON | TOML |
| Файлы темы | `theme.json` | `Meta.toml`, `Definition.toml` |
| Необязательные ресурсы | Фоновое изображение, шрифты | Фоновое изображение, шрифты, иконки, CSS |
| Система иконок | Нет | Да |
| Внедряемый CSS | Нет | Да (`Inject.css`) |
| Определение переменных | Плоское и ручное | По категориям с автоматическими префиксами |
| Секция фона | Поля в корне | `[background]` в `Definition.toml` |
| Статус | Устаревший | Рекомендуемый |

### Распространённые CSS-переменные фронтенда

Эти переменные необязательны, но часто используются фронтендом и функцией `extract_preview` для генерации предпросмотра темы:

| Переменная | Типичное использование |
|---|---|
| `--bg-main` | Основной фон. |
| `--bg-card` | Фон карточки или панели. |
| `--bg-sidebar` | Фон боковой панели. |
| `--accent` | Акцентный цвет. |
| `--text-primary` | Основной цвет текста. |

В V2 эти переменные происходят из секций `colors`, `backgrounds` и `text` с соответствующими префиксами.


## Примечания и лучшие практики
- **Используйте semver** в поле `version`, чтобы сохранять понятную историю изменений.
- **Сжимайте изображения**: фоновые изображения имеют лимит 25 МБ, а иконки — 2 МБ. Лёгкие изображения ускоряют загрузку.
- **Предпочитайте SVG или WEBP** для иконок, так как они обеспечивают лучшее качество и сжатие.
- **Проверяйте TOML/JSON** перед упаковкой. Синтаксические ошибки приводят к тому, что CubicLauncher молча игнорирует тему при листинге.
- **Держите пути относительными** внутри ZIP, чтобы пакет оставался переносимым.
- **Документируйте лицензии** на шрифты и изображения, которые вы включаете, в своём `theme.md`.
- **Избегайте конфликтов переменных** в V2: если две секции генерируют одну и ту же CSS-переменную, тема выдаст предупреждение, и одно значение перезапишет другое.
- **Тестируйте тему локально** перед публикацией с помощью `import_theme_zip` или соответствующих команд.
