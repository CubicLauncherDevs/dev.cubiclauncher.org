## Установка

CubicLauncher доступен в AUR (Arch User Repository). Вы можете установить его с помощью предпочитаемого помощника AUR или собрать официальный пакет из `PKGBUILD`.

### Из AUR

```bash
yay -S cubiclauncher
```

```bash
paru -S cubiclauncher
```

Если у вас не установлены `yay` или `paru`, ознакомьтесь с их документацией:
- [yay](https://github.com/Jguer/yay)
- [paru](https://github.com/Morganamilo/paru)

Вы также можете посмотреть пакет по адресу: <https://aur.archlinux.org/packages/cubiclauncher>

:::warning Пакет AUR больше не получает обновлений
Пакет `cubiclauncher` по-прежнему публикуется в AUR, но пока **мы не можем его обновлять**, поэтому он не будет получать новые версии CubicLauncher. Установка или обновление с помощью `yay -S cubiclauncher` или `paru -S cubiclauncher` даст вам последнюю версию, опубликованную в AUR, но не самые новые.

Чтобы оставаться в актуальном состоянии, пересоберите официальный `PKGBUILD`: измените строку `pkgver=`, запустите `updpkgsums`, а затем `makepkg -si`. См. [Обновление CubicLauncher](#обновление-cubiclauncher).
:::

### Сборка PKGBUILD

Если вы предпочитаете компилировать вручную, можете использовать официальный `PKGBUILD`. Клонировать весь репозиторий или устанавливать зависимости вручную не нужно: сам `PKGBUILD` загружает исходный код, а `makepkg` занимается разрешением и установкой необходимых зависимостей.

:::warning Локальная компиляция необязательна.
Arch Linux — дистрибутив с моделью rolling release, поэтому версии библиотек и зависимостей часто меняются.
Двоичные файлы, созданные GitHub Actions (Ubuntu), могут оказаться несовместимыми или не запускаться в обновлённых системах Arch.
Компиляция программы в вашей собственной системе гарантирует совместимость с установленными библиотеками и даёт пакет, адаптированный к вашей среде.
:::

```bash
mkdir cubiclauncher-build
cd cubiclauncher-build

wget https://raw.githubusercontent.com/CubicLauncherDevs/CubicLauncher/main/dist/arch/PKGBUILD
makepkg -si
```

## Обновление CubicLauncher

Пакет AUR не обновляется, поэтому переход на новую версию требует пересборки `PKGBUILD`. Если вы уже скачали его, заново с нуля скачивать не нужно.

Перейдите в каталог, куда вы скачали `PKGBUILD`, откройте файл и измените значение `pkgver` на новую версию:

```bash
cd cubiclauncher-build
nano PKGBUILD
```

Найдите строку `pkgver=` и обновите её. Затем автоматически обновите контрольные суммы с помощью `updpkgsums`:

```bash
updpkgsums
```

Наконец, пересоберите и установите обновлённый пакет:

```bash
makepkg -si
```

:::warning ПРИМЕЧАНИЕ
Команда `updpkgsums` входит в пакет `pacman-contrib`. Если он у вас не установлен, его можно получить с помощью `sudo pacman -S pacman-contrib`.
:::

### Автообновление не работает в Arch

CubicLauncher включает встроенный механизм автообновления, который скачивает последний двоичный файл из GitHub Releases и заменяет текущий исполняемый файл. В Arch Linux этот механизм **не работает**, и исправить это невозможно по следующим причинам:

1. **Системные разрешения**: при установке через `makepkg -si` двоичный файл копируется в `/usr/bin/cubiclauncher` с правами **root** (`root:root`). У обычного пользователя нет прав на запись в `/usr/bin`, поэтому автообновление не может перезаписать файл.

2. **Несовместимость двоичных файлов**: даже если запустить автообновление от имени root, предварительно скомпилированные двоичные файлы из GitHub Actions слинкованы с библиотеками Ubuntu, что может вызывать сбои в Arch.

3. **Философия Arch**: в Arch Linux правильный способ обновления любой программы — через `pacman`. Использование внешних средств автообновления обходит пакетный менеджер, оставляя систему в несогласованном состоянии (pacman не будет знать, что двоичный файл был заменён).

## Распространённые проблемы

### NVIDIA и Wayland: проблемы с графикой

Если CubicLauncher открывает пустое окно, мерцает или аварийно завершается при изменении размера, см. [Проблемы с графикой в Linux: NVIDIA и Wayland](/docs/ru-RU/guides/nvidia-wayland). Там описаны `WEBKIT_DISABLE_COMPOSITING_MODE=1 cubiclauncher`, менее ограничительные альтернативы и проверка KMS. Локальная сборка не гарантирует решения этих проблем с отрисовкой.

### Ошибка загрузки зависимостей (404)

Если во время установки вы видите ошибки, подобные следующим:

```text
error: failed retrieving file 'gst-plugins-good-*.pkg.tar.zst'
error: failed retrieving file 'gst-plugins-bad-*.pkg.tar.zst'
error: failed to commit transaction (failed to retrieve some files)
```

Вероятно, одно из зеркал, настроенных в вашей системе, устарело. Прежде чем снова запускать `makepkg`, обновите базу данных пакетов и синхронизируйте систему:

```bash
sudo pacman -Syu
```

Если проблема сохраняется, обновите список зеркал или попробуйте более новые зеркала:

```bash
sudo pacman -S reflector
sudo reflector --latest 20 --sort rate --save /etc/pacman.d/mirrorlist
sudo pacman -Syyu
```

После обновления системы запустите снова:

```bash
makepkg -si
```

:::warning ВНИМАНИЕ
Эта ошибка не связана с CubicLauncher или PKGBUILD; она возникает, когда зеркало Arch Linux ещё не синхронизировало самые последние пакеты.
:::
